# Gameplay rules

What the code does, one topic per file. Each numbered rule has a test in
the suite named after its file (`@Suite("docs/rules/<file>")` in
`ios/Tests/SpecTests/Rules/`), unless the file says otherwise. Change a rule
and its test in the same commit. The intent behind Play is in
[gameplay](../gameplay.md).

Play:

- [Next run](next-run.md): what Play picks, and on which side.
- [Drill](drill.md): where a Drill run starts.
- [Freeform](freeform.md): runs from move one, in any of your lines.
- [Opponent](opponent.md): what the other side plays in Drill.
- [Growth](growth.md): gaps, and adding moves inside a run.
- [Past prep](past-prep.md): misses, blunders, the book phase and endgame rules.
- [Scoring](scoring.md): points, combo, moments and missions.
- [Scheduling](scheduling.md): cards, need, staleness and weakness, in runs.
- [Play screen](play-screen.md): how a run is shown and ended.

Everywhere:

- [Playbook](playbook.md): book moves only.
- [Saves](saves.md): bringing older saves up to date.
